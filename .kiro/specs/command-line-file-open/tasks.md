# Implementation Plan

- [x] 1. 起動引数の分類ルールと検証の土台を整える
- [x] 1.1 起動引数をファイル候補と未対応通知へ分類できるようにする
  - 実行ファイル名を除いた引数列から、ファイル候補を入力順のまま収集できるようにする。
  - `--` で始まる引数はファイル候補へ入れず、後続の通知対象として分離できるようにする。
  - 完了時には、引数 0 件・1 件・2-10 件のいずれでも起動モードが 1 つに確定し、11 件目以降のファイル候補は起動対象に含まれない。
  - _Requirements: 1.1, 1.2, 2.1, 2.2, 3.1, 3.2, 4.1, 4.3, 4.4_
- [x] 1.2 引数分類の境界条件を自動テストで固定する
  - 引数なし、単一ファイル、複数ファイル、11 件以上、未対応 `--` の混在をそれぞれ再現できるようにする。
  - ファイル候補の順序維持、10 件上限、未対応通知の保持が崩れないことを確認する。
  - 完了時には、起動モード判定の主要分岐がテストで可視化され、将来の CLI 拡張で回帰が見つかる状態になる。
  - _Requirements: 1.1, 1.2, 2.1, 2.2, 3.1, 3.2, 4.1, 4.3, 4.4_

- [x] 2. 単一インスタンス起動で初回表示状態を準備できるようにする
- [x] 2.1 (P) 起動前に単一ファイルを既存ビューアー状態へ折りたためるようにする
  - 起動時に渡された 1 件のファイルを、既存の読み込み経路と同じ契約でドキュメント表示またはエラー表示へ変換できるようにする。
  - UI の初回表示前に状態だけを確定し、追加の画面更新を前提にしない開始経路を保つ。
  - 完了時には、読み込み成功時は対象ファイルを開いた初期状態になり、読めないファイルや非 UTF-8 ファイルではそのインスタンス内でユーザー向けエラー状態が見える。
  - _Requirements: 1.1, 1.3, 1.4, 2.3_
  - _Boundary: AppController Startup Bootstrap_
- [x] 2.2 起動前状態の成功系・失敗系を近接テストで固定する
  - 起動前の単一ファイル準備について、成功、ファイル読み込み失敗、非 UTF-8 の各分岐を検証する。
  - 単一ドキュメント前提が維持され、起動前処理が UI 副作用を持たないことを確認する。
  - 完了時には、起動時ファイルの成否が既存ビューアー状態へどう反映されるかをテストで追える。
  - _Requirements: 1.3, 1.4, 2.3_

- [x] 3. 起動オーケストレーションを単一起動と複数起動へ統合する
- [x] 3.1 起動計画に応じて空表示と単一ファイル表示を切り替えられるようにする
  - 起動時に作成した計画を使って、ファイルなしでは空のビューアーを、単一ファイルでは初回表示にその内容またはエラー状態を反映する。
  - 未対応 `--` 引数の通知は標準エラーへ 1 行ずつ出しつつ、ファイル起動の継続を妨げないようにする。
  - 完了時には、未対応引数だけの起動では空ビューアーが表示され、未対応引数と有効ファイルが混在しても単一ファイル起動が継続する。
  - _Requirements: 1.1, 1.2, 4.2, 4.3, 4.4_
- [x] 3.2 複数ファイル時は親プロセスから子インスタンスへ分岐する
  - 2-10 件のファイル候補では、親プロセス自身がビューアーを持たず、各ファイルごとに独立した子起動を試行する。
  - 子プロセスには 1 件のファイルだけを渡し、未対応 `--` 通知は親で打ち切って再送しないようにする。
  - 完了時には、複数ファイル指定で 1 インスタンス複数表示が起きず、開けるファイルは継続して起動し、子起動自体の致命失敗だけが startup failure として扱われる。
  - _Requirements: 2.1, 2.2, 2.3, 3.1, 3.2, 4.2, 4.3_

- [x] 4. 起動フロー全体の回帰を検証する
- [x] 4.1 起動オーケストレーションの統合テストを追加する
  - 空起動、単一ファイル起動、未対応 `--` と有効ファイルの混在、複数ファイル分岐をそれぞれ再現できるようにする。
  - 親プロセスが複数ファイル時にビューアーを生成しないことと、単一ファイル時に初回表示で最終状態へ到達することを確認する。
  - 完了時には、起動経路の主要分岐と `stderr` 通知の継続条件が統合テストで見える。
  - _Requirements: 1.1, 1.2, 2.1, 2.2, 2.3, 4.2, 4.3, 4.4_
- [x] 4.2 Windows 実行環境でコマンドライン起動のスモークを確認する
  - 実ファイル、非 UTF-8 ファイル、複数ファイル指定の代表ケースで、設計どおりの初回表示と分岐結果を目視確認できるようにする。
  - 単一ファイルではファイル名と本文またはエラー文言が初回表示に現れ、複数ファイルでは 1 ファイル 1 インスタンスになることを確認する。
  - 完了時には、Windows の実行環境でこの仕様のユーザー価値が最低限成立していることを確認できる。
  - _Requirements: 1.1, 1.3, 1.4, 2.1, 2.3_
