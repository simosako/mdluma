# Brief: drag-and-drop-file-open

## Problem
MDLuma をローカル Markdown ビューアーとして使うユーザーは、エクスプローラーからファイルをウィンドウへ直接ドロップして開きたい。現状は起動引数経由では開けるが、GUI 上の自然な入力経路であるドラッグ＆ドロップでは開けず、閲覧までに余分な操作が必要になる。

## Current State
既存の `command-line-file-open` では、起動時に渡されたファイルパスを解釈して 1 ファイルごとに 1 インスタンスで開く経路がある。一方で、起動後の既存ウィンドウに対してファイルドロップを受け付ける経路はなく、エクスプローラーからの通常ファイルドロップでファイルを開けない。

## Desired Outcome
ユーザーがエクスプローラーから通常のローカルファイルを MDLuma ウィンドウへドロップすると、最大 10 件までのファイルを開けるようにする。1 件目は現在のウィンドウで開き、2 件目から 10 件目までは別ウィンドウで開き、11 件目以降とフォルダは無視する。特殊ドロップは対象外とする。

## Approach
Sciter.js SDK のドラッグ＆ドロップ入力を現在のビューアーウィンドウで受け付け、通常のローカルファイルだけを抽出する。抽出後は単一ドキュメントビューアーの前提を維持するため、先頭 1 件を現在のウィンドウの既存ファイルオープン経路へ流し、残り 2-10 件は既存の複数起動方針に合わせて別インスタンスで開く。

## Scope
- **In**: エクスプローラーからの通常ローカルファイルのドロップ受理、複数ファイル対応、最大 10 件の上限制御、先頭 1 件を現在ウィンドウで開く挙動、2-10 件目を別ウィンドウで開く挙動、フォルダの無視
- **Out**: 特殊ドロップ形式、仮想項目、ショートカット解決、フォルダ展開、11 件目以降の処理継続、複数ファイルを 1 ウィンドウに同時表示する機能、タブ管理、ドロップ演出の高度な UI フィードバック

## Boundary Candidates
- ウィンドウ入力境界: Sciter 側でのドラッグ＆ドロップ受付と通常ファイル抽出
- ドキュメント起動境界: 抽出済みファイルを現在ウィンドウで開く処理と追加ウィンドウ起動処理

## Out of Boundary
- コマンドライン引数仕様そのものの拡張や変更
- エクスプローラー特殊項目や他アプリ由来ドラッグデータの解決
- フォルダや非ファイル項目を辿って Markdown を探す処理
- ドラッグ中ハイライトなどの見た目改善

## Upstream / Downstream
- **Upstream**: Sciter ウィンドウイベント、既存のファイルオープン経路、既存の複数インスタンス起動経路
- **Downstream**: 将来のドロップ可能状態の UI フィードバック、特殊ドロップ対応、関連するファイルオープン入力経路の統合整理

## Existing Spec Touchpoints
- **Extends**: なし
- **Adjacent**: `command-line-file-open`（複数ファイル時の別インスタンス方針と隣接）、`minimal-markdown-viewer`（単一ドキュメント閲覧体験と隣接）

## Constraints
Windows 11/10 を優先対象とし、Sciter.js SDK のイベントモデルに従うこと。対象はエクスプローラーからの通常ローカルファイルに限定し、フォルダは無視する。単一ドキュメントビューアーの設計を崩さず、軽量性と実装の単純さを優先する。Sciter 配布条件は既存プロジェクト方針の範囲内で扱う。
