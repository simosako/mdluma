# Implementation Plan

- [x] 1. 基盤: 本文選択 feature の DOM 契約を固定する
- [x] 1.1 本文 `article` に選択境界と読み取り専用マーカーを持たせる
  - 本文ラッパーが UI スクリプトから安定して特定できる属性を持ち、既存の読み取り専用表示契約を維持する。
  - 文書を再描画しても本文選択 feature が同じ境界を参照できるようにする。
  - 生成される HTML 断片で本文境界と読み取り専用属性の両方が確認できる状態で完了とする。
  - _Requirements: 1.1, 3.1_
  - _Boundary: DefaultHtmlShell_

- [x] 1.2 本文用アンカーとコピー状態表示アンカーを UI shell に置く
  - 本文のみを選択対象として識別できる DOM アンカーを追加し、本文外 UI と責務を分離する。
  - コピー失敗を局所表示できる専用アンカーを追加し、既存のロード系エラー表示と混同しない配置にする。
  - shell を読めば本文選択対象とコピー状態表示先の両方が確認できる状態で完了とする。
  - _Requirements: 1.1, 1.4, 4.1_
  - _Boundary: UiAssets_

- [x] 2. Core: 本文選択とコピー操作を UI 層で成立させる
- [x] 2.1 (P) 本文だけを選択可能にし、複数行選択を視覚的に判別できるようにする
  - 本文表示領域では選択を阻害せず、タイトルバーや本文外 UI では既存の非選択前提を維持する。
  - 選択範囲が複数行にまたがっても連続した本文として扱われ、ユーザーが選択状態を見分けられる見た目にする。
  - 同じ文書内で別の本文箇所を選択し直したときは、最新の選択範囲へ自然に更新されるようにする。
  - 実際の UI 資産上で本文は選択でき、本文外 UI は本文選択として扱われない状態で完了とする。
  - _Requirements: 1.2, 1.3, 1.4, 3.1, 3.2_
  - _Depends: 1.1, 1.2_
  - _Boundary: UiAssets_

- [x] 2.2 (P) 一般的なコピー操作で選択中の表示テキストだけをクリップボードへ送る
  - `Ctrl+C` と `Meta+C` の両方を扱い、本文選択がある場合だけコピー処理を実行する。
  - コピー対象は Markdown ソースではなく表示中の本文テキストとし、改行をまたぐ選択でも読み取り順を保つ。
  - 選択範囲を持つときだけコピーが走り、選択なしでは表示状態を変えない状態で完了とする。
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 3.2_
  - _Depends: 1.1, 1.2_
  - _Boundary: CopyInteractionController_

- [x] 2.3 コピー成功時のクリアと失敗時の局所メッセージ表示を追加する
  - コピー成功時は失敗メッセージを残さず、失敗時だけユーザーが認識できる文言を本文表示を壊さずに示す。
  - コピー失敗を UI 局所状態として扱い、アプリ終了、文書再読み込み、編集系機能追加を引き起こさないようにする。
  - コピー失敗後も同じ文書とウィンドウ状態のまま閲覧を続けられる状態で完了とする。
  - _Requirements: 3.4, 4.1, 4.2, 4.3_
  - _Depends: 1.2, 2.2_
  - _Boundary: CopyInteractionController_

- [x] 3. Integration: viewer の文書切り替え境界へ接続する
- [x] 3.1 文書切り替え時に旧 selection とコピー状態を新しい文書へ持ち越さない
  - 既存の全文再読み込み境界に合わせて、旧 DOM に属する本文選択とコピー状態表示が自然に破棄されるようにする。
  - 新しい Markdown ファイルを開いた直後は、以前の選択ハイライトもコピー失敗表示も残らない初期状態から始まるようにする。
  - 文書 A の選択やコピー状態が文書 B に引き継がれないことを確認できる状態で完了とする。
  - _Requirements: 3.3, 4.2_
  - _Depends: 1.1, 1.2, 2.3_
  - _Boundary: AppController, SciterWindow, CopyInteractionController_

- [x] 3.2 選択とコピーを viewer-only の責務に閉じ込める
  - 選択とコピーの実装が Rust 側の新しい command、編集経路、保存経路を必要としない構成を保つ。
  - 本 feature によって元の Markdown 内容が変更されず、読み取り専用ビューアーとしての境界が接続後も維持されるようにする。
  - 実装全体を見て選択とコピーが UI 層だけで完結し、文書内容変更経路が増えていない状態で完了とする。
  - _Requirements: 3.1, 3.4, 4.3_
  - _Depends: 2.2, 2.3, 3.1_
  - _Boundary: AppController, SciterWindow, CopyInteractionController_

- [x] 4. Validation: 契約と回帰を検証する
- [x] 4.1 HTML shell と UI 資産の契約テストを追加する
  - 本文選択境界、読み取り専用マーカー、コピー状態アンカー、選択用スタイルが埋め込み資産に含まれることを固定する。
  - コピー関連スクリプトが本文選択参照、ショートカット判定、クリップボード呼び出しを備えることを検証する。
  - 契約崩れがテストで即座に検出できる状態で完了とする。
  - _Requirements: 1.1, 1.3, 1.4, 2.1, 2.2, 4.1_
  - _Depends: 1.1, 1.2, 2.1, 2.2, 2.3_
  - _Boundary: DefaultHtmlShell, UiAssets, CopyInteractionController_

- [x] 4.2 コピー成功、選択なし、失敗、文書切り替えの結合検証を追加する
  - 選択ありコピーでクリップボード書き込みが 1 回だけ行われ、選択なしではコピーも失敗表示も発生しないことを確認する。
  - 同じ文書内で選択箇所を切り替えたときに、最新の選択内容がコピー対象として扱われることを確認する。
  - クリップボード失敗時は局所メッセージが更新され、文書切り替え後はその状態が残らないことを確認する。
  - コピーと文書切り替えの主要経路で回帰を自動検出できる状態で完了とする。
  - _Requirements: 2.3, 2.4, 3.2, 3.3, 4.1, 4.2_
  - _Depends: 3.1, 3.2, 4.1_
  - _Boundary: AppController, SciterWindow, CopyInteractionController_

- [x] 4.3 Sciter 実機または統合環境で本文選択と Clipboard 挙動を確認する
  - 本文を複数行選択して `Ctrl+C` したときに、表示順どおりの文字列が貼り付けできることを確認する。
  - 文書 A から文書 B へ切り替えたときに、選択ハイライトとコピー状態が引き継がれないことを確認する。
  - クリップボード失敗を再現した条件でも、ウィンドウが閉じず本文表示を維持したまま閲覧を続けられることを確認する。
  - Sciter 固有の選択とクリップボード連携が実運用に耐えることを確認できる状態で完了とする。
  - _Requirements: 2.1, 2.3, 3.3, 4.1, 4.2_
  - _Depends: 3.1, 3.2, 4.2_
  - _Boundary: SciterWindow, CopyInteractionController_
