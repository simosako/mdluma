# Implementation Plan

- [x] 1. 絶対パス化された保持パスを読み込み境界で確定する
- [x] 1.1 ドキュメント入力を読み込み前に絶対パス化し、その結果だけを保持パスと親ディレクトリの基準にする
  - GUI と起動引数のどちらから渡された入力でも、同じ絶対パス化ルールを最初に適用する。
  - ファイル読込、表示用ファイル名の抽出、親ディレクトリの導出をすべて絶対パス化後の値から行う。
  - 完了時は、同じ文書を別経路で開いても読み込み済みモデルの保持パスと親ディレクトリが同一形式になる。
  - _Requirements: 1.1, 1.2, 1.3, 2.1, 2.2_
- [x] 1.2 空パスと絶対パス化失敗入力を読み込み済み状態へ進めず、未確定パスを保持しない
  - 空パスは明示的に失敗として扱い、その他のパスも絶対パス化に失敗した時点で読込処理を停止し、既存の読込失敗エラー経路へ返す。
  - 失敗時に絶対パス化前の入力値から読み込み済みドキュメントや親ディレクトリを生成しない。
  - 失敗理由は最低限 `debug_log!` に出力し、調査可能な状態を残す。
  - 完了時は、空パスまたは絶対パス化失敗入力で成功側モデルが一切生成されず、失敗が観測できる。
  - _Requirements: 3.1, 3.2_

- [x] 2. 読み込み後の状態でも絶対パス化された保持パスを維持する
- [x] 2.1 レンダリング結果へドキュメント位置を引き継ぎ、表示用ファイル名とは別の保持値として残す
  - 読み込み済み入力が持つ絶対パス化された保持パスと親ディレクトリを、HTML 化後のドキュメントモデルへ失わず伝播する。
  - 表示用ファイル名の扱いは従来どおり葉名専用のままにして、保持パスの責務と混在させない。
  - 完了時は、ロード後状態に表示名とは別の絶対パス化された保持パスが存在し、表示契約は変わらない。
  - _Requirements: 1.4, 2.1, 2.3_
- [x] 2.2 ビューアー状態が絶対パス化された保持パスと親ディレクトリを一貫した組として保持する
  - 読み込み成功時の状態更新は、同じロード結果から作られた保持パス、親ディレクトリ、表示名だけを採用する。
  - 文脈参照が必要な箇所では、入力生パスではなく保持済みの絶対パス化後親ディレクトリを基準にする。
  - 完了時は、現在表示中ドキュメントの位置情報を状態から直接確認しても、開始経路に依存しない一貫した値になる。
  - _Requirements: 1.4, 2.2, 2.3_

- [x] 3. 開く経路ごとの制御を共通契約へそろえる
- [x] 3.1 GUI と startup の両経路が同じ読み込み契約を通って成功状態へ遷移するよう揃える
  - GUI で選択したパスと起動時に受け取ったパスを、別々の絶対パス化実装へ分岐させず同じ読込契約へ流す。
  - 起動引数に相対パスが来ても、成功時は GUI と同じ意味の保持パスで表示開始できるようにする。
  - 完了時は、どちらの入口から開いてもロード成功後の現在ドキュメント位置が同一形式で観測できる。
  - _Requirements: 1.2, 1.3, 2.2_
- [x] 3.2 読み込み失敗時は既存表示を保ったままエラー表示へ切り替える
  - 既存文書を表示中に新しい入力の絶対パス化が失敗した場合、失敗した入力で現在文書を置き換えない。
  - startup 初期読込失敗と再読込失敗の両方で、成功状態へ進まない既存エラー制御を維持する。
  - 完了時は、失敗後も既存文書が残るケースと初期エラー表示になるケースを振る舞いで区別して確認できる。
  - _Requirements: 3.1, 3.3_

- [x] 4. 絶対パス化契約を回帰テストで固定する
- [x] 4.1 ローダーとレンダラーの単体テストで絶対パス化契約を固定する
  - 相対パス、`.` / `..` を含む入力、空パス、絶対パス化失敗入力を対象に、保持パスと親ディレクトリの生成規則を検証する。
  - レンダリング後も保持パスと親ディレクトリが変化しないことを確認する。
  - 既存のログ捕捉手段がある場合は `debug_log!` 出力を確認し、ない場合でも失敗経路への分岐と成功側モデル未生成が検証される。
  - _Requirements: 1.1, 1.4, 2.1, 3.1, 3.2_
- [x] 4.2 アプリケーション統合テストで入口差異と表示維持の回帰を防ぐ
  - GUI 経由のロード、startup 引数の相対パスロード、表示中の失敗置換防止をそれぞれ確認する。
  - ファイル名表示は従来どおり葉名のみを維持しつつ、内部位置情報は絶対パス化された保持パスで統一されることを確かめる。
  - 完了時は、入口ごとの差異や失敗時の表示破壊が統合テストで再発防止される。
  - _Requirements: 1.2, 1.3, 2.2, 2.3, 3.3_

- `RenderedDocument` struct gained `path: PathBuf` field; all construction sites (including html_shell.rs tests) were updated mechanically.
- `design/backlog.md` was inadvertently modified across tasks (backlog reordering). Not functional.
