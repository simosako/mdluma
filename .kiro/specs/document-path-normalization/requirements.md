# 要件定義書

## 概要
この機能は、MDLuma が読み込んだ Markdown ドキュメントの位置情報を、GUI から開いた場合とコマンドライン引数から開いた場合で同じ意味の形にそろえることを目的とする。ドキュメントの保持パスは必ず絶対パス化された保持パスとして扱い、後続の表示状態や相対参照の基準が起動経路によってぶれないことを要求する。

## 境界コンテキスト
- **対象範囲**: GUI のファイル選択と起動引数の両方で受け取ったドキュメントパスを、読み込み済みドキュメント状態で同一形式の絶対パス化された保持パスとして扱うこと。そのパスに基づくドキュメント位置の解釈を一貫させること。
- **対象外**: UI 上の表示文言やファイル名表示の全面変更、複数ドキュメント管理、シンボリックリンク解決や実体パス比較のような追加同一性判定、ファイル関連付けや OS 側の引数生成ロジックの変更。
- **隣接前提**: OS、ファイルダイアログ、外部ランチャーは開く対象のパスを MDLuma に渡す責務を持つ。この機能は、受け取ったパスを読み込み済み状態へ取り込む前に同一形式へそろえるが、外部システム側のパス生成方式までは規定しない。

## 要件

### 1. 読み込み済みドキュメントの保持パス絶対化
**目的:** GUI 操作や起動引数の違いを意識せずに MDLuma を使うユーザーとして、現在開いているドキュメントの位置情報が常に同じ形式の絶対パス化された保持パスとして扱われてほしい。これにより、開き方によって内部状態や後続処理が変わらない。

#### 受け入れ基準
1. When ユーザーが GUI のファイル選択から Markdown ファイルを開く, the MDLuma shall その読み込み済みドキュメントの保持パスを絶対パス化された保持パスとして扱う。
2. When ユーザーが起動引数で Markdown ファイルを指定して開く, the MDLuma shall その読み込み済みドキュメントの保持パスを絶対パス化された保持パスとして扱う。
3. When 同じ Markdown ファイルが GUI 経由と起動引数経由のいずれかで開かれる, the MDLuma shall 開始経路に依存しない同一形式の絶対パス化された保持パスを読み込み済みドキュメント状態で用いる。
4. The MDLuma shall 読み込み済みドキュメントごとに、表示用ファイル名とは別に絶対パス化された保持パスを保持する。

### 2. 絶対パス化された保持パスに基づく文脈の一貫性
**目的:** ドキュメントに依存した表示文脈を利用するユーザーとして、開き方が違っても同じファイルは同じ場所にあるものとして扱われてほしい。これにより、相対参照や関連処理の基準がぶれない。

#### 受け入れ基準
1. When 読み込み済みドキュメントの親ディレクトリ情報が必要になる, the MDLuma shall 絶対パス化された保持パスに対応する親ディレクトリを基準として扱う。
2. When 同じ Markdown ファイルが異なる開始経路で開かれる, the MDLuma shall そのドキュメント位置に基づく文脈を同一の親ディレクトリ基準で扱う。
3. While 読み込み済みドキュメントが表示されている, the MDLuma shall ドキュメント位置の絶対パス化有無にかかわらず既存のファイル名表示体験を維持する。

### 3. 絶対パス化不能時と空パス時の失敗扱い
**目的:** 開こうとしたドキュメントの位置を正しく確定できない場合でも MDLuma を使うユーザーとして、中途半端な状態で表示が進まないでほしい。これにより、誤った文書位置を前提にした表示や後続処理を避けられる。

#### 受け入れ基準
1. If 受け取ったドキュメントパスが空である、または絶対パス化された保持パスとして確定できない, the MDLuma shall そのドキュメントを読み込み済み状態として扱わず、ユーザー向けエラーを表示する。
2. If ドキュメントパスの絶対パス化に失敗した, the MDLuma shall 絶対パス化前の入力パスを読み込み済みドキュメント状態へ保持しない。
3. When 既存のドキュメント表示中に新しく開こうとしたパスの絶対パス化が失敗する, the MDLuma shall 失敗したドキュメントへ現在表示内容を置き換えない。
