# Implementation Plan

- [x] 1. Foundation: 外部エディタ設定変更の前提契約を整備する
- [x] 1.1 外部エディタ設定変更コマンドを定義してUIイベント経路へ接続する
  - `External Editor Setting` 操作を既存の menu action / xcall / command 変換経路に追加する。
  - 既存の `External Editor` 起動コマンド経路は互換を維持する。
  - 完了時、`External Editor Setting` 操作が1回のクリックで1回だけアプリ層に到達することをテストで確認できる。
  - _Requirements: 1.1, 1.2_

- [x] 1.2 外部エディタ実行ファイル選択ダイアログ契約を追加する
  - Windows標準ダイアログを使って実行ファイルを1件選択する契約を追加する。
  - Selected/Cancelled/Failure の結果を既存ダイアログ契約と同じ方針で返せるようにする。
  - 完了時、選択時はパスが返り、キャンセル時は設定更新が起きない前提をテストで確認できる。
  - _Requirements: 1.2, 1.3, 2.4_

- [x] 1.3 失敗系検証のためのテスト注入点を整備する
  - 設定保存失敗と外部エディタ起動失敗を安定再現できるテスト注入点を既存テストダブル方針で追加する。
  - 成功系既存テストを壊さず、失敗系のみを独立して再現できるようにする。
  - 完了時、保存失敗ケースと起動失敗ケースを個別に再現できるテストが追加される。
  - _Requirements: 4.1, 4.2, 4.3_

- [x] 2. Core: 設定変更導線と保存動作を実装する
- [x] 2.1 (P) `...` メニューに `External Editor Setting` を追加する
  - `External Editor` の下に `External Editor Setting` を表示する。
  - 既存のメニュー順序と既存項目の動作を壊さない。
  - 完了時、`...` メニューを開くと `External Editor` 配下に新規項目が表示されることを画面とテストで確認できる。
  - _Requirements: 1.1_
  - _Boundary: MoreMenuUi_

- [x] 2.2 `External Editor Setting` 操作でOS標準ダイアログを開く
  - 設定項目の操作で外部エディタ選択ダイアログを起動する。
  - ダイアログの結果はアプリ層へ正しく橋渡しし、保存判断を可能にする。
  - 完了時、項目選択でダイアログが表示され、キャンセル時に設定値が不変であることを統合テストで確認できる。
  - _Depends: 1.1, 1.2, 2.1_
  - _Requirements: 1.2_

- [x] 2.3 ダイアログのSelected/Cancelledに応じて設定更新を分岐する
  - Selected のときのみ `external_editor` を保存し、Cancelled のときは設定を不変に保つ。
  - 保存失敗は次タスクで扱うため、このタスクでは成功時更新とキャンセル不変のみを確定する。
  - 完了時、Selected でのみ設定値が更新され、Cancelled では更新されないことをテストで確認できる。
  - _Depends: 2.2_
  - _Requirements: 1.3, 2.1, 2.4_

- [x] 3. Integration: 起動先解決と失敗時継続契約を統合する
- [x] 3.1 設定保存後の再起動読込と起動先反映を統合する
  - 保存済み `external_editor` が次回起動時に読み込まれ、起動先解決へ反映されることを保証する。
  - 設定保存フローと既存起動フローの接続を確認する。
  - 完了時、再起動相当のテストで保存済み設定が起動先として使われることを確認できる。
  - _Depends: 2.3_
  - _Requirements: 2.2, 2.3, 3.1_

- [x] 3.2 既存 `External Editor` 起動で設定値優先・未設定時フォールバックを維持する
  - 設定済みパスがある場合はその実行ファイルのみを起動対象として扱う。
  - 設定未指定時のみ `notepad.exe` を使う。
  - 完了時、1回の操作で1つの実行ファイルのみ起動試行されることをテストで確認できる。
  - _Depends: 3.1_
  - _Requirements: 3.1, 3.2, 3.3_

- [x] 3.3 設定保存失敗時のユーザー可視エラー表示を追加する
  - 設定保存に失敗した場合は利用者に分かるエラー表示へ遷移する。
  - エラー表示後も現在の閲覧セッションを継続可能にする。
  - 完了時、保存失敗を再現したテストでエラー表示と継続利用の両方を確認できる。
  - _Depends: 1.3, 2.3_
  - _Requirements: 4.3_

- [x] 3.4 外部エディタ起動失敗時の継続動作を回帰防止する
  - 起動失敗時にユーザー可視エラーを表示し、終了要求を行わないことを維持する。
  - 既存の成功時のみ終了する契約を維持する。
  - 完了時、起動失敗ケースでセッション終了しないことと文書表示継続をテストで確認できる。
  - _Depends: 1.3, 3.2_
  - _Requirements: 4.1, 4.2_

- [x] 4. Validation: 受け入れ観点の検証を完成させる
- [x] 4.1 設定変更導線の統合テストを追加する
  - メニュー表示、コマンド変換、ダイアログ起動、Selected/Cancelled分岐を検証する。
  - 完了時、設定変更導線の主要分岐が自動テストで再現できる。
  - _Depends: 2.1, 2.2, 2.3_
  - _Requirements: 1.1, 1.2, 1.3, 2.1, 2.4_

- [x] 4.2 保存・再起動・起動先反映のE2E観点を検証する
  - 設定保存後の再起動で保存済み設定が実際の起動先解決に使われることを検証する。
  - 完了時、設定値の永続化から外部エディタ起動までの一連フローが検証可能になる。
  - _Depends: 3.1, 3.2_
  - _Requirements: 2.2, 2.3, 3.1, 3.2_

- [x] 4.3 失敗系受け入れテストを追加する
  - 設定保存失敗と外部エディタ起動失敗の双方で、エラー表示とセッション継続を確認する。
  - 完了時、失敗系の受け入れ基準が回帰テストで担保される。
  - _Depends: 3.3, 3.4_
  - _Requirements: 4.1, 4.2, 4.3_
