# Brief: external-editor-integration

## Problem
MDLuma の利用者は Markdown を閲覧中に、内容を編集したい場面では別のエディタへ素早く移りたい。現在は MDLuma から開いているファイルを外部エディタへ渡す導線がなく、手動でエディタを開いて対象ファイルを探す必要がある。

## Current State
MDLuma にはタイトルバーの `...` メニューと設定ファイルによる一部設定保存はあるが、外部エディタ起動機能は存在しない。現在開いているファイルのフルパスを外部プロセスへ渡して起動し、成功時にビューアーを終了する経路も未実装である。

## Desired Outcome
利用者はタイトルバーの `...` メニューから `External Editor` を選ぶだけで、現在 MDLuma で開いている Markdown ファイルを外部エディタで開ける。設定が未指定なら Windows では `notepad.exe` を使い、設定ファイルで指定があればその実行ファイルを使う。起動成功時のみ MDLuma は終了し、起動失敗時は終了せずエラーを表示する。ファイル未オープン時はメニュー項目を無効化する。

## Approach
実装は最小構成とし、設定ファイルに外部エディタ実行ファイルパスを保持する単一項目を追加する。`...` メニューに `External Editor` を追加し、現在開いているファイルのフルパスを単一引数として対象エディタを起動する。Windows 既定値は `notepad.exe` とし、起動成功時のみ MDLuma を閉じる。この方式は既存のメニュー、設定、現在ファイル追跡、プロセス起動の責務に自然に沿い、ビューアーを編集機能へ肥大化させない。

## Scope
- **In**: `...` メニューへの `External Editor` 項目追加、`Font` の下への配置、ファイル未オープン時の無効化、設定ファイルへの外部エディタパス項目追加、未設定時の `notepad.exe` フォールバック、現在開いているファイルのフルパスを引数にした外部エディタ起動、起動成功時の MDLuma 終了、起動失敗時のエラー表示と継続動作
- **Out**: MDLuma 自体の編集機能、外部エディタの参照ダイアログ UI、複数引数やテンプレート付きコマンドライン指定、OS 既定関連付けの解決、外部エディタ起動後の双方向連携や監視

## Boundary Candidates
- タイトルバー `...` メニューとコマンド通知の UI 導線
- 設定ファイルでの外部エディタ実行ファイルパス管理
- 現在表示中ドキュメントのフルパス取得と外部プロセス起動
- 起動成功時終了 / 失敗時継続のアプリケーション制御

## Out of Boundary
- 外部エディタそのものの設定画面やブラウズ UI
- ファイル保存、差分監視、自動再読込など編集ワークフロー全体の統合
- 複数ドキュメント同時受け渡しやタブ管理
- Windows 以外の既定エディタ定義の具体化

## Upstream / Downstream
- **Upstream**: 現在開いているドキュメント状態、タイトルバー `...` メニュー、既存の設定ファイル保存基盤、Windows 上のプロセス起動
- **Downstream**: 将来の設定 UI 追加、最近使ったエディタ選択、外部アプリ連携拡張

## Existing Spec Touchpoints
- **Extends**: なし
- **Adjacent**: `font-settings`（同じ `...` メニュー配下の導線）、`command-line-file-open`（現在ドキュメントのファイルパス前提）、`minimal-markdown-viewer`（単一ドキュメント閲覧体験を維持）

## Constraints
Windows 11/10 を優先し、既定の外部エディタは `notepad.exe` とする。MDLuma は軽量ビューアーのままとし、編集責務を内包しない。外部エディタ起動は現在開いているファイル 1 件のみを対象とし、フルパスを単一引数として渡す。起動成功時のみ MDLuma を終了し、起動失敗時は終了せず利用者へエラーを表示する。repo 全体の既存課題として Sciter 配布条件の明文化不足は残るが、この機能は新規依存を追加しない。
